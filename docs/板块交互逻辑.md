## 一、系统架构总览

工作台 = **一个前端单页 + 一个本地服务 + 一批脚本**，全部跑在你自己电脑上，数据不经过云端（除了调用 DeepSeek / TikHub 两个外部 API）。

```
┌─────────────────────────────────────────────────────────────┐
│  浏览器  dashboard/index.html（7 个板块，纯前端）              │
│  数据来源：dashboard/data.js + dashboard/me.js                │
└──────────────────────────┬──────────────────────────────────┘
                           │  HTTP（localhost:8420，有密码门）
┌──────────────────────────▼──────────────────────────────────┐
│  后端  scripts/serve.mjs                                     │
│  · 静态文件服务器（no-store，刷新即最新）                      │
│  · API 接口（10+ 个）                                         │
│  · 任务队列（后台串行执行脚本，前端轮询状态）                   │
└───────┬──────────────────┬──────────────────┬───────────────┘
        │ 拉数据            │ AI 生成           │ 构建
        ▼                  ▼                  ▼
  xhs_*.mjs            ai_*.mjs          build_dashboard.mjs
  (TikHub API)         (DeepSeek API)    (合成 data.js/me.js)
```

## 二、七大板块详解

### 1. 我的内容（me）
- **职责**：展示你自己账号的数据（主页信息 + 每篇笔记的赞/藏/评/转），按分类、爆款统计。
- **数据来源**：`me.json`（由 `xhs_me.mjs` 从 TikHub 拉取）。
- **触发**：数据管理页「刷新我的数据」按钮，或首次 onboarding。
- **产出**：`me.js`（供前端显示）+ `analysis/me-analysis.json`（供灵感库第 1 源使用）。

### 2. 灵感库（vault）
- **职责**：15 条高潜力视频选题，是整条内容流水线的起点。
- **生成逻辑**（`ai_oracle.mjs` + `prompts/oracle.md`，三源合一）：
  1. **我的账号分析**（`analysis/me-analysis.json`）→ 决定"写什么方向"
  2. **同赛道创作者**（`creators/*.json`，看板里拉过详情的博主）→ 学"怎么写能爆"
  3. **素材库**（`materials/materials.json`，长文先用 Flash 提炼"核心观点+角度+金句"）→ 提供"新料"
- **产出**：`vault/vault.json`，每条选题带唯一 id（`v+时间戳到秒+序号`，如 `v20260821231714-01`）、标题、角度、为什么有效、格式、`style_hint`（借鉴谁/借鉴什么）。
- **模型**：默认 V4 Pro（可下拉切换）。

### 3. 草稿（draft）
- **职责**：把选题写成完整视频文案 + 分镜。
- **生成逻辑**（`ai_draft.mjs`）：选题 + 声音指南（`voice/voice-guide.md`，你的写作风格）+ 起草规则（`prompts/draft.md`）。
- **改稿**（`ai_revise.mjs`）：按你的修改意见（或评审团意见）重写。
- **存储**：`drafts/index.json`，按选题 id 键控，每个选题独立一篇，含 `council`（评审结果）。
- **模型**：默认 V4 Flash（快），可下拉切换。

### 4. 评审团（council）
- **职责**：对某篇草稿，6 位评委独立打分（1-10）+ 给具体改法。
- **评委**（`prompts/council.md`）：David Perell（观点密度）、Sean Puri（钩子）、Morgan Housel（真实耐久）、Ann Handley（句子工艺）、Nicolas Cole（结构适配）、**AI 味鉴别师（有否决权）**。
- **规则**：7 分=能发但没记忆点；AI 味鉴别师 <7 分触发否决（需改稿）。
- **存储**：评审结果写回 `drafts/index.json` 对应草稿的 `council` 字段。
- **模型**：默认 V4 Pro，可下拉切换。

### 5. 小红书创作者（creators）
- **职责**：你的同赛道对标博主看板，是灵感库第 2 源的数据基础。
- **拉取逻辑**（详见下文"数据拉取"）：
  - 「发现创作者」：关键词搜索 → 广度+互动排序 → 黑名单过滤 → `xhs_authors.json`
  - 「添加博主」：粘贴链接/ID → 深拉 40 条笔记 → `creators/<id>.json`
- **数据来源**：`xhs_authors.json`（粗略列表）+ `creators/*.json`（深度笔记）。
- **叠加规则**：新发现**合并**进旧列表，不覆盖。

### 6. 素材库（materials）
- **职责**：存放你收藏的完整文章，供灵感库第 3 源参考。
- **入口**：
  - 手动导入（标题 + 链接 + 备注）
  - 浏览器插件（`browser-extension/`）一键抓取**全文**（不截断）
- **存储**：`materials/materials.json`。
- **用途**：灵感库生成前，先提炼每篇长文的核心观点/角度/金句，再参与选题合成。

### 7. 数据管理（admin）
- **职责**：所有"拉数据"操作的入口 + 任务日志。
- **按钮**：刷新我的数据 / 添加博主 / 发现创作者 / 修复笔记链接。
- **任务日志**：显示后台任务队列的执行状态和日志（失败时来这里看原因）。

## 三、板块间的数据流与交互

**核心主线：灵感库 → 草稿 → 评审团 → 改稿（循环）**

```
  数据管理 ──拉取──► 创作者看板 ──┐
  数据管理 ──拉取──► 我的内容 ────┤
  素材库（插件/手动）────────────┤
                                 ▼
                           灵感库（三源合一，15 条选题）
                                 │ 用选题写草稿
                                 ▼
                           草稿（选题 → 文案+分镜）
                                 │ 开始评审
                                 ▼
                           评审团（6 评委打分+意见）
                                 │ 按意见修改
                                 └──► 回到草稿，循环到满意
```

**关键交互细节**：

1. **选题 id 是三板块的"钥匙"**：灵感库/草稿/评审团的下拉共享同一个"当前选题"（存 localStorage），草稿选 vXX，评审团自动对应 vXX，无需重选。
2. **每个选题独立存档**：草稿、评审都按选题 id 分开存，互不干扰。
3. **选题 id 永久唯一**：灵感库每次全量重写，选题 id 用时间戳生成（不会重复），所以旧的草稿/评审不会错位；旧选题被重写后，其草稿会以「📁 历史草稿」形式保留在下拉里。
4. **模型可独立选**：灵感库/草稿/评审团各自有模型下拉（Flash 快 / Pro 强），互不影响，选择记住在浏览器。

## 五、任务队列机制

- 所有耗时操作（拉数据、AI 生成）都走 `serve.mjs` 的**后台任务队列**，**串行执行**（一个跑完再跑下一个）。
- 前端轮询 `/api/jobs` 显示状态：排队中 → 运行中 → 完成/失败。
- 失败时日志留在「数据管理」页，可展开看具体原因。
- 触发任务后**别急着刷新/重复点**，否则会排队堆积。
